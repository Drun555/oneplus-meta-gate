# OnePlus Meta Gate 1.2.0

Модуль KernelSU / KernelSU Next для OnePlus Pad 3, crDroid 12.12
v12.12-20260916, Android 16 (security patch 2026-09-01).

## Изменение 1.2

Физическая Escape на клавиатуре OnePlus Pad 3 посылает Linux `KEY_BACK`
(scan code 158). В её аппаратной раскладке исправлена одна строка:
`key 158 BACK` → `key 158 ESCAPE`. После этого применяется существующий
пропуск Escape в приложения. Кнопка/жест «Назад» на экране и другие клавиатуры
не изменяются. Artemis не модифицируется.

Подменяется также `/odm/usr/keylayout/Vendor_22d9_Product_3869.kl`.
Его исходный SHA-256 проверяется перед включением. Для чтения раскладки
драйвером ввода после установки нужна перезагрузка.

## Поведение

- SEARCH блокируется во всех окнах.
- Escape передаётся всем приложениям как `KEYCODE_ESCAPE`; системная обработка
  и преобразование в Back отключены. Собственное действие Escape внутри
  приложения сохраняется. Meta+Escape вне исключений блокируется как Meta-сочетание.
- Левая и правая Meta и сочетания с Meta блокируются вне списка исключений.
  Пока Meta удерживается вне исключений, сочетания с ней поглощаются целиком.
- В активном окне Artemis (`com.limelight.noir`), Moonlight (`com.limelight`),
  Windows App (`com.microsoft.rdc.androidx`) и старого Microsoft Remote Desktop
  (`com.microsoft.rdc.android`) Meta и сочетания доставляются приложению,
  минуя системные обработчики Android. Далее отправкой хосту занимается клиент.
- На заблокированном экране исключения не действуют.
- Список применяется к окнам приложения, в том числе вне удалённой сессии.
  В split-screen исключение определяется окном с фокусом клавиатуры.
- Alt+Tab, Ctrl и другие сочетания без Meta модуль не меняет.

## Установка / отключение

Установить ZIP через KernelSU и перезагрузиться. Чтобы вернуть исходное
поведение, отключить или удалить модуль в KernelSU и перезагрузиться.
Физический системный раздел не изменяется. Не нужны Zygisk, LSPosed или metamodule.

Файл `/system/framework/services.jar` подменяется bind mount на ранней стадии
загрузки. Установщик и скрипт загрузки сверяют SHA-256 исходного файла.
После обновления прошивки модуль отключится, если хеш изменится; потребуется
пересборка под новый services.jar. Установщик допускает обновление поверх активной версии 1.1 с тем же services.jar.

Если загрузка не завершится, следующая загрузка автоматически отключит модуль
по оставшемуся маркеру `boot-pending`. Для этого при зависании перезапустить
планшет. Также доступен штатный безопасный режим KernelSU. Завершённая загрузка
удаляет маркер через 15 секунд после `sys.boot_completed=1`.

При доступном root ADB можно отключить модуль вручную:

```
adb shell su -c 'touch /data/adb/modules/oneplus_meta_gate/disable'
adb reboot
```

## Изменение приложений

После первой загрузки отредактировать от root
`/data/system/meta_gate/apps.conf`: одно точное имя пакета на строку.
Пустой список блокирует Meta везде. Изменения читаются при следующем событии
Meta, не чаще раза в две секунды. SEARCH остаётся заблокированным.
Кнопка Action в KernelSU показывает список и журнал загрузки.

## Реализация и проверка

Добавлен класс `local.codex.metagate.MetaGate`; изменены только три метода
`InputManagerService`: `interceptKeyBeforeQueueing`,
`interceptKeyBeforeDispatching`, `dispatchUnhandledKey`.
Остальные DEX-файлы services.jar сохранены побайтово. Изменённый classes2.dex
собран smali 2.5.2, вспомогательный класс — javac 17 + Android D8.
Проверен ART verifier на самом планшете; выполнены 30 проверок логики на Android,
включая отпускание обычной клавиши после отпускания Meta, отсутствие фокуса,
экран выключен, разрешённое/запрещённое приложение, подавление fallback,
передачу Escape обычным и удалённым приложениям, сохранение отдельной клавиши Back.
После перезагрузки 29.09.2026 подтверждены успешная загрузка, активный bind mount
и отсутствие ошибок MetaGate / AndroidRuntime. В отдельном тестовом приложении
проверен реальный путь InputDispatcher: вне списка получены только A и Escape;
в списке получены также Meta и Meta+A с сохранённым метасостоянием. SEARCH не
доставляется в обоих случаях. Ввод ограничивался UID тестового приложения;
после проверки приложение удалено и исходный список исключений восстановлен.
Получение событий конкретным удалённым хостом требует проверки в сессии клиента.
Windows App на момент сборки на планшете не установлен.

Root-задача проверки не вводит клавиши в удалённую сессию. Включённый Key Mapper
или другая служба специальных возможностей может дополнительно перехватывать
ввод; такие существующие настройки этот модуль не меняет.
